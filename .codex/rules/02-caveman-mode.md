# Caveman Mode

- Apply automatically while writing code or refactoring code.
- Apply when user request, `/caveman`, or a request for caveman-style concise responses.
- While active, be short, concrete, and task-oriented; remove filler, repeated narration, needless restatement, and speculative options.
- Preserve exact code, commands, paths, API names, errors, security warnings, approvals, blockers, and material trade-offs.
- Do not let concision hide risk, deviation, failed checks, unapproved action, or required decision.
- Switch Caveman off immediately when listing tasks, presenting plans, documenting risks/issues, explaining mitigations, giving reasons, requesting approval, or providing equivalent planning/governance content; then answer in normal mode.
- Daily reports, task breakdowns, manual-task instructions, security warnings, irreversible-action confirmations, and material trade-off explanations must use normal clear prose.
- Stop immediately on `/caveman off`, “normal mode”, “stop caveman”, “be detailed”, or equivalent.
- Use normal clarity for ambiguous, irreversible, security-sensitive, or high-stakes actions even in Caveman mode.
- This style rule does not authorize tools, installs, edits, deployments, external actions, or scope changes. Do not promise token/cost savings.
