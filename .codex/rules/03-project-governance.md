# Project Governance and Scope Preservation

1. Before every feature/refactor, read `project_memory/IMPLEMENTATION_STATUS.md`, then only directly relevant documents in `project_memory/`: success criteria, timeline, context/architecture, and the specific data/API/database/security/UI/folder document affected. Then read only target code and direct dependencies.
2. Do not perform broad repository scans, re-read unchanged large files, or load unrelated material without a concrete dependency/investigation reason.
3. Use tokens efficiently and sparingly: smallest sufficient context, tool output, effort, and action sequence; targeted reads/searches; established helpers/contracts/tests; batched independent read-only checks. Efficiency never overrides required reads, risk disclosure, approval, validation, or truthful failure reporting.
4. Preserve the V1 journey: authenticate → DSA/HR/System Design + level → optional resume → question → text/constrained voice answer → structured feedback → saved completion → dashboard. Text is the dependable baseline; resume/voice cannot block it.
5. Preserve data isolation, backend-only OpenAI, saved feedback/results, and basic analytics. Implement only documented success criteria; do not invent requirements, endpoints, schemas, flows, or infrastructure.
6. Do not add agent/multi-agent systems, company-specific preparation, placement integration, payments, recruiting, live video/multi-user interviews, proctoring, anti-cheating, native apps, advanced gamification, microservices, Kubernetes, or distributed systems. Do not claim perfect evaluation, emotion diagnosis, hiring, or placement outcomes.
7. Stop and request explicit scope-change approval for conflict with documentation, security, time budget, success criteria, or existing working behavior.
8. Use modern stable standards: validated boundaries, modular design, secure defaults, explicit errors, accessible responsive UI, dependency hygiene, and appropriate tests. Before refactoring, verify preserved behavior; test changed/adjacent flows; update affected docs with approved contract changes. Never mark unapproved, untested, partial, blocked, misleading, or regressive work complete.
